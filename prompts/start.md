# 새 세션에 전달할 시작 프롬프트

이 저장소로 MonoGPT·Timely AI·ChatGPT를 비교해 주세요. 이전 대화·개인 보고서·앱 캐시를 참고하지 말고 공용 파일과 이번 사용자가 제공한 정보로 진행하세요.

먼저 `AGENTS.md`와 `docs/REPRODUCIBLE-RUN.md`를 읽고, 실행 안내의 준비 단계에서 연결한 설정·측정·평가·사이트별 지침을 확인하세요. 실행 순서는 새로 설계하지 말고 `REPRODUCIBLE-RUN.md`의 기본 경로를 따르세요.

- 기본 후보는 저비용 GPT·Claude·Gemini이며, 최종 질문은 `cases/core.json`의 core-v2입니다. 기본 배분은 GPT 24회, Claude 8회, Gemini 8회로 총 40회입니다. 실제 UI 지원과 승인 범위를 확인하고, 모델을 조용히 생략하거나 `cases/smoke.json`의 개발용 질문을 최종본에 섞지 마세요.
- 같은 비교 묶음의 모델·추론·질문·첨부를 맞추세요. 이번 승인 범위에서 추론만 다르면 `reasoning_mismatch_policy=auto_exploratory`로 참고 비교를 허용합니다. 엄격 비교와 분리하고, 사용자가 엄격 비교만 원하거나 의도가 불명확하면 한 번 확인하세요. 제공하지 않는 모델은 모델 없음으로 표시합니다.
- 사이트·로그인 상태·정확한 요청 수·원화 환산율을 확인하되 이미 제공한 내용은 재질문하지 마세요. 사용자가 금액 상한 없는 고정 요청 수를 승인했다면 RUNBOOK의 해당 경로를 사용하세요. 자동 충전·결제·임의 재전송은 하지 마세요.
- 검토·등록된 비개인 자료만 첨부하세요. 계정·인증·실제 결과·개인 보고서는 Git에 올리지 마세요.
- 모든 모델의 UI 조작은 `docs/BROWSER-FLOW.md`의 관측 → 한 번 조작 → 결과 확인을 따르세요. 현재 주소·대상 버튼·설정·첨부 내용이 맞는지 확인하며, 메뉴가 다르면 비슷한 버튼을 대신 누르지 마세요. 오류는 해당 단계부터 복구하고 완료 요청을 재전송하지 마세요.
- 기본 영속 타이머와 기존 record/report를 사용하고, 별도 측정·기록·보고서 코드를 새로 만들지 마세요. 매 요청 status로 시간 저장을 확인하세요. 누락은 과거 시각을 꾸미거나 유료 재전송해서 채우지 마세요.
- `docs/EVALUATION.md`와 `examples/review-example.json`의 근거 수준으로 채점·총평·서비스별 차이·UX를 작성하세요. 예시는 가상이므로 실제 답변이나 점수로 복사하지 마세요.

마지막으로 audit의 보완 목록을 확인하고, 실행 안내의 전달 전 체크리스트에 따라 상세 PDF·엑셀·모델별 선그래프 PDF 3파일을 검증해 주세요. 사용자에게 보이는 폴더의 경로, 모델별 실행 범위, 시간·비용 누락과 한계를 함께 알려 주세요. 파일 생성이나 자동테스트 통과를 전체 실측 성공으로 표현하지 마세요.
