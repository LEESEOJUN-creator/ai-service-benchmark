# 다른 사용자용 시작 프롬프트

이 저장소의 AGENTS.md, README.md, docs/STATUS.md, docs/PROTOCOL.md, docs/BROWSER-FLOW.md, docs/RUNBOOK.md, docs/EVALUATION.md를 먼저 읽어 주세요.

이어서 이번 실행 대상의 개별 조작 지침을 읽어 주세요. MonoGPT는 docs/sites/monogpt.md, Timely AI는 docs/sites/timely.md, ChatGPT는 docs/sites/chatgpt.md입니다. 다른 사이트의 지침은 docs/BROWSER-FLOW.md에서 확인하고, 지침이 없는 사이트를 이미 검증된 것처럼 실행하지 마세요.

버튼을 찾을 때 개별 지침의 위치·이름·확인 신호를 사용하되, 현재 화면에서 다시 확인하세요. MonoGPT의 심층 사고와 심층분석, Timely의 추론 설정과 심층 리서치를 구분하세요. 새 채팅 및 첫 전송 후 설정이 유지됐는지 확인하고, 미확인 추론 수준으로 동일 조건 비교를 확정하지 마세요.

config/benchmark.json을 기준으로 사전 점검과 실행 계획을 작성하세요. 연결된 브라우저 도구가 실제로 제공되는지 확인하고, 구현되지 않은 기능이나 확인하지 않은 사이트를 실행 가능하다고 말하지 마세요.

기본 질문은 cases/core.json의 core-v2 8개입니다. cases/smoke.json은 개발용 회귀 예시이므로 개인 최종 보고서에 섞지 마세요. 배치별 승인 범위와 활성 질문 목록은 local/ 설정에 고정하고 기본 요청 상한을 임의로 늘리지 마세요. 최종 질문은 보고서에 한 번씩만 수록하고 서비스별 답변은 질문 ID로 연결하세요.

MonoGPT, Timely AI, ChatGPT를 반드시 동일 모델·동일 추론 수준·동일 프롬프트·동일 첨부 파일로 비교하세요. ChatGPT의 Chat/Work도 실행 조건으로 고정·기록하세요. Gemini/Claude를 ChatGPT에서 지원한다고 가정하지 말고 3사 공통 후보부터 확인하세요. 비싼 모델은 피하고, 모델이 없으면 임의 대체하지 말고 공통 후보를 다시 확인하세요. 사용자 후보명은 실제 UI와 문서로 확인하기 전까지 확정 모델 ID로 취급하지 마세요.

사이트 주소·계정·예산이 없으면 필요한 사항을 구체적으로 알려 주세요. 이미 설정되거나 승인된 내용을 반복 질문하지 마세요. 비밀번호·쿠키는 코드나 Git에 저장하지 마세요.

파일은 검토된 비개인 자료만 사용하세요. 숨겨진 사용량 메뉴를 포함해 실행 전후 잔액을 확인하고 차감량을 계산하세요. 시간과 비용을 확인하지 못하면 미측정으로 남기세요. 중복 전송을 피하고 모든 시도를 기록하세요.

브라우저 연결과 조건 검증이 끝나면 승인된 범위만 실행하세요. 엄격 금액 상한 계획과 가격 미확정 요청 수 제한 파일럿을 구분하고 RUNBOOK의 요건을 따르세요. 결과에는 입력, 답변 원문, 생성 파일 검증, 측정 근거, 오류, 품질 평가를 포함하세요. 서비스명을 가린 평가와 검증 가능한 정답을 우선 사용하세요.

완료 시 HTML 보고서와 비교표, 증거 위치를 안내하세요. 아직 구현되지 않은 산출물을 만들었다고 주장하지 마세요.

최종 비교표의 열은 MonoGPT·Timely AI·ChatGPT를 유지하세요. Claude/Gemini를 제공하지 않는 ChatGPT 칸은 **모델 없음**으로 표시하고, 비용·시간·품질은 null로 둡니다. 모델은 있는데 설정 확인이 안 된 경우는 **조건 미확정**, 아직 보내지 않은 경우는 **미실측**, 도구 한도로 실행 불가한 경우는 **도구 한도**로 구분하세요. 이 상태들을 모두 모델 없음이나 0점으로 합치지 마세요.
