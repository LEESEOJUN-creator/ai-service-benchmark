# MonoGPT 조작 지침서

데스크톱 Chrome 한국어 화면 기준. UI 버전은 실행 기록에 별도로 남긴다.

계정·요금제·모델·창 크기에 따라 UI가 다를 수 있다. 아래 위치는 고정 좌표가 아닌 탐색 힌트다. 접근성 이름과 현재 화면을 함께 확인하고, 이전 요소 ID를 재사용하지 않는다.

먼저 [공통 브라우저 흐름](../BROWSER-FLOW.md)과 [비교·측정 규약](../PROTOCOL.md)을 읽는다. 이 문서에는 계정명·잔액·실제 답변·스크린샷을 넣지 않는다.

## 버튼 위치 빠른 안내

| 작업 | 버튼 위치·경로 | 누른 뒤 확인할 것 |
|---|---|---|
| 접속 | https://monogpt.kr/ | 로그인된 계정의 채팅 화면인지 확인 |
| 사이드바 펼치기 | 화면 왼쪽 위 `사이드바 열기` | 새 채팅·대화 목록 표시 |
| 새 대화 | 사이드바 위쪽 `새 채팅` (`⌘⇧O` 표기) | 기존 메시지가 없는 빈 입력 화면 |
| 모델 | 화면 위쪽 왼편 현재 모델명과 아래 화살표 | 선택 모델의 정확한 이름 |
| 추론 | 입력창 아래 `옵션 열기` → `심층분석` → 단계 | 선택 단계와 전송 후 요청별 적용 근거 |
| 웹 검색 | 옵션 줄 `검색` 토글 | 토글 상태 / 보라색 웹 검색 표시 |
| 리서치 | 옵션 줄 `심층 사고` (Deep Research) | 일반 추론과 별도 기능임을 구분 |
| 문서 첨부 | 입력창 `+` (`파일 첨부`) → `파일 첨부` | 첨부 이름·개수·완료 상태 |
| 이미지 첨부 | 입력창 `+` → `이미지 첨부`; 옵션 줄 `이미지`도 표시 | 실제 이미지 미리보기·완료 상태 |
| 보내기 | 입력창 오른쪽 화살표 (`보내기`) | 사용자 메시지가 정확히 1개 추가됨 |
| 크레딧 | 사이드바 맨 아래 `크레딧 잔여량` | 상세 잔액·소진 내역·사용량 |
| 답변 복사 | 답변 바로 아래 `답변 복사` | 복사된 답변 원문 |
| 답변 저장 | 답변 아래 `질문·답변 저장` | 다운로드 형식·파일 존재 여부는 별도 검증 |
| 표 조작 | 답변의 표 영역 (전용 내보내기 기능 미확인) | 실제 다운로드와 파일 내용은 별도 검증 |

## 확인 범위

- 확인: 기존 로그인 세션 접속, 새 채팅, 모델 메뉴, GPT-6 Sol 추론 옵션, 첨부 메뉴, 크레딧 상세·사용 내역, 답변의 모델·effort·검색 표시.
- 확인: 프롬프트에서 XLSX 생성 요청 후 실제 다운로드, 시트·숫자·수식·재계산 검사. 답변 저장과 표 전용 내보내기는 별도 미검증이다.
- 미검증: 로그아웃 상태의 로그인/SSO/2차 인증, PNG/TXT 외 전체 확장자 제한, 타 사용자 계정 재현.
- 표시 모델명은 UI 선언이며 실제 공급자 백엔드 버전은 미검증이다.

## 상세 조작

- 접속 주소는 `https://monogpt.kr/`이다. 저장된 탭 ID를 믿지 말고 현재 URL을 대조하며 유사 도메인으로 이동하지 않는다.
- TXT/이미지 첨부는 이름·완료 표시뿐 아니라 가능한 미리보기 내용을 승인 파일과 대조한다. 다른 본문이 보이면 해당 항목을 전송하지 않고 선택/업로드 상태부터 확인한다. 파일명만 바꿔 재첨부한 것을 해결 근거로 삼지 않는다. 상세 복구는 [공통 흐름](../BROWSER-FLOW.md)을 따른다.

### M1. 빈 대화부터 시작

1. 왼쪽 위 사이드바 버튼으로 메뉴를 펼친다.
2. 위쪽 `새 채팅`을 누른다.
3. 이전 질문·답변이 사라지고 `어떻게 도와드릴까요?` 또는 빈 입력창이 보이는지 확인한다. 특히 답변 복사 버튼 등 기존 답변 흔적이 0개인지 확인한 뒤 전송한다. 사이드바가 접혀 있으면 먼저 펼쳐 `새 채팅`을 실제로 누른다.
4. 모델과 옵션을 다시 설정한다. URL이 `/`라고 해서 새 대화인 것은 아니다. 새 탭에서 홈에 접속했는데 직전 대화가 복원된 경우가 있었다.
5. 새 채팅 이후 옵션이 접히거나 심층분석이 꺼질 수 있으므로 이전 대화 설정을 물려받았다고 가정하지 않는다.

### M2. 모델 선택

1. 위쪽 현재 모델명 → `ChatGPT`, `Gemini`, `Claude` 등 계열을 펼친다. 계열 옆 숫자는 모델 개수이므로 고정 문자열로 저장하지 않는다.
2. 계열 아래에서 정확한 모델명을 고른다. 예: `ChatGPT` → `GPT-6 Sol`.
3. 상단 선택 모델명이 갱신됐는지 확인한다. `Eco`, `Chat`, `Tools`, `Google Search` 등 접미사가 다르면 같은 조건으로 취급하지 않는다.
4. 메뉴에 검색 입력창과 `전체 보기로 전환`도 있다. 정확한 이름을 못 찾을 때 보조 경로로 쓰되 현재 화면에서 다시 확인한다.
5. 메뉴 아래 `모델 변경 방식`에는 `매번 묻기`, `현재 대화 이어가기`, `새 대화 시작`이 표시된다. 기존 대화에서 모델을 바꿀 때 대화 경계가 달라질 수 있으므로 독립 테스트는 M1부터 시작한다. 불필요하게 전역 선호 설정을 바꾸지 않는다.
6. 현재 모델명 옆 `모델 선택 가이드`는 기능·설명 확인용이다. 설명에 추론 조절 가능이라고 적힌 것과 실제 옵션이 선택된 것은 다르다.

### M3. 추론·검색 설정

1. 입력창 아래 옵션이 안 보이면 `옵션 열기`를 누른다. 이미 옵션 줄이 펼쳐져 있으면 이 버튼이 보이지 않을 수 있다.
2. `심층분석`을 켠다. GPT-6 Sol에서 `낮음 / 보통 / 높음 / 매우 높음` 버튼이 나타난다.
3. 목표 단계의 버튼을 누른 뒤 선택 색상 또는 접근성 선택 상태를 확인한다. 토글이 켜진 것만 확인하고 단계 확인을 생략하지 않는다.
4. `심층 사고`는 별도의 Deep Research 기능이다. 간결/표준/상세/심화 같은 리서치 옵션을 일반 reasoning 단계로 매핑하지 않는다.
5. `검색` 토글을 목표 상태로 맞춘다. `Google 검색` 칩은 검색 엔진 선택과 관련된 UI이므로 칩이 보인다는 사실만으로 검색 활성이라고 판단하지 않는다.
6. 전송 후 답변에 있는 모델명, `effort: low` 같은 표시, 검색 상태 배지를 확인한다. 다음 입력용 검색 토글과 완료된 답변의 검색 배지가 다를 수 있다. 각 요청의 증거를 우선한다.

### M4. 첨부 진입과 안전 점검

1. 입력창 왼쪽 `+` (`파일 첨부`)를 누른다.
2. 메뉴에서 문서는 `파일 첨부`, 이미지는 `이미지 첨부`를 선택한다. 같은 메뉴에 `YouTube URL`, `Google 검색`, `웹페이지 참조`, `문서함 참조`가 있어 혼동하기 쉽다.
3. 문서 첨부 버튼의 안내는 `최대 100MB`였다. 실제 형식별 제한·서버 수락 여부는 별도 확인해야 한다.
4. 옵션 줄의 `이미지` / `파일`에서 실제 PNG/TXT 선택·업로드를 검증했다. 그 외 형식의 성공은 별도 확인한다.
5. 승인·내용 검토·해시 등록이 끝난 동일 파일만 선택한다. 업로드 후 파일명, 개수, 오류, 완료 상태를 확인한 뒤 질문을 보낸다. 로컬 파일 선택만으로 업로드 완료라고 하지 않는다.

### M5. 소진내역과 답변 보존

1. 사이드바 아래 `크레딧 잔여량` → `크레딧 상세 정보`를 연다.
2. `크레딧 지급·할당 내역`에서 개인/조직, 공유 소진 여부를 확인한다.
3. 아래 `사용 내역`에서 테스트 시각과 모델에 대응하는 새 행을 찾는다. `일시`, `사용 내용·모델`, `변동`, `할인 충전` 열을 기록한다.
4. 순소진은 해당 요청 차감액에서 확인된 할인 충전액을 뺀 값이다. 서로 무관한 환급을 합산하지 않는다. 행에 대화 ID가 없으면 시간·모델에 근거해 대응했다는 한계를 남긴다.
5. 여러 페이지면 아래 `다음 ›`로 이동한다. 전체 `xlsx 다운로드`는 무관한 사용 내역까지 포함할 수 있으므로 기본 수집 방법으로 쓰지 않는다.
6. 답변의 `답변 복사`와 `질문·답변 저장`을 구분한다. `답변 다시 생성`, `메시지 수정 및 재전송`, `AI 윤문`, `문서 생성(v2)` 등은 추가 실행이 될 수 있으므로 결과를 읽기 위해 누르지 않는다.

### MonoGPT 측정 원칙 요약

- 상단 모델 메뉴 → 모델 계열 → 정확한 모델 선택.
- 입력창 옵션의 **심층분석** → 낮음/보통/높음/매우 높음. **심층 사고**는 별도의 Deep Research 기능이므로 혼동하지 않는다.
- 검색 토글을 전송 전에 확인한다. 전송 후 입력창 값만으로 이전 요청의 설정을 단정하지 말고 답변의 검색 상태 배지와 `effort` 표시를 확인한다.
- 사이드바 하단 크레딧 잔여량 → 크레딧 상세 정보 → 사용 내역.
- 테스트 시각·모델과 대응하는 새 사용 내역을 우선 사용한다. 변동과 할인 충전(Event)을 별도로 기록하고 순소진을 계산한다. 행에 대화 ID가 없으면 시간·모델에 의한 대응이라는 한계를 남긴다.
- 조직 공용 잔액이면 다른 사용자 사용이 섞일 수 있다. 전체 잔액 차이는 보조 검증이며 개별 내역과 불일치하면 미확정으로 남긴다.
## 추가 실측 주의점

- 검토된 PNG와 TXT 업로드 후 파일명·진행 상태·완료를 확인하는 경로를 검증했다. 지원 확장자 안내만 보고 모든 형식을 검증했다고 쓰지 않는다.
- 파일 기능 버튼 → 파일 선택 → 분석 준비 완료를 기다린다. TXT는 RAG 임베딩 단계에서 별도 크레딧 차감이 관측됐다.
- 공유 소진 계정에서는 소진 내역을 대조한다. 채팅과 다른 ‘프롬프트 고도화’ 내역이 같은 시간에 나타날 수 있어 잔액 차이만으로 귀속하지 않는다.
- 이번 Gemini 3.5 Flash-Lite에서는 심층 사고 미지원으로 표시돼 기본 추론을 유지했다. Timely 보통과 추론 단계가 일치한다고 단정하지 않는다. 사용자가 지정한 경우에만 탐색 비교로 기록한다.
- Sonnet 5.5: 옵션 → 적응형 사고 켜기 → 낮음/보통/높음/매우 높음/최대. 낮음 선택 후 응답 footer `effort: low` 확인.
- 생성 파일 카드 내부 `파일 다운로드`로 저장한다. 카드 본문은 미리보기일 수 있다. 다운로드 이벤트가 타임아웃이어도 실제 파일이 저장됐는지 먼저 확인하고, 생성 요청을 재전송하지 않는다.
- 문서 생성 시 상단 선택 모델과 소진내역 모델명이 다르게 관측됐다. 모델명이 충돌하면 동일 모델 점수에서 제외하고 서비스 기능 결과로 분리한다. 어느 쪽이 실제 백엔드인지는 추측하지 않는다.
- 소진내역 증거는 이번 테스트에 대응하는 행만 저장한다. 전체 페이지·전체 내역 다운로드로 무관한 개인 기록을 수집하지 않는다.
