# 공통 브라우저 실행 흐름

이 문서는 UI 확인 체크리스트·예외 처리를 다룬다. 처음부터 끝까지의 실행 순서는 [실행 안내](REPRODUCIBLE-RUN.md)를 따른다. 버튼 위치와 사이트 고유 동작은 아래 개별 지침에서 관리한다. 독립 자동 실행 프로그램이 아니라 지원되는 브라우저 도구를 사용하는 에이전트용 지침이다.

## 1. 읽는 순서와 사이트별 지침

1. [비교·측정 규약](PROTOCOL.md): 동일 모델·추론·입력, 비용·시간·평가 기준.
2. 이 문서: UI 확인과 예외 처리.
3. 이번 실행에 포함된 사이트의 개별 지침을 **실제 조작 전에** 읽는다.

| 서비스 | 조작 지침 | 관리할 내용 |
|---|---|---|
| MonoGPT | [모노GPT 지침](sites/monogpt.md) | 버튼 위치, 모델·추론·검색·첨부, 소진내역, 주의사항 |
| Timely AI | [타임리 지침](sites/timely.md) | 버튼 위치, 모델·추론·도구·첨부, 사용 현황, 주의사항 |
| ChatGPT | [ChatGPT 지침](sites/chatgpt.md) | 로그인·모델 메뉴 탐색 완료, Chat/Work 구분 및 동일 조건 매핑 미검증 |

다른 사용자용 [시작 프롬프트](../prompts/start.md)는 이 문서와 실행 대상의 개별 지침을 함께 읽도록 안내한다. 새 사이트는 `docs/sites/<service-id>.md`에 작성하고 이 표에 연결한다. 사이트 연결 데이터는 루트 `sites/`에서 관리하며 [사이트 연결 규격](../sites/CONTRACT.md)을 따른다.

## 2. 공통 확인 원칙

- UI는 계정·요금제·모델·창 크기에 따라 다르므로 매 실행마다 현재 화면에서 재확인한다. 좌표와 요소 ID를 저장해 재사용하지 않는다.
- 메뉴·버튼의 존재, 클릭 성공, 실제 업로드/다운로드/생성 성공을 구분한다. 사이트별 지침의 확인 범위를 읽고 미검증 기능을 지원 확정으로 취급하지 않는다.
- 사이트가 선언한 모델명만으로 실제 백엔드 버전 일치를 단정하지 않는다.
- 로그인 확인을 위해 기존 세션을 로그아웃하지 않는다. 인증이 필요하면 사용자가 승인한 사이트의 실제 로그인 화면을 따르며 CAPTCHA·추가 인증은 도구 정책에 따라 처리한다.
- 계정·비밀번호·쿠키는 문서나 Git에 기록하지 않는다. 실제 잔액·답변·화면 원본은 `runs/`에 저장한다. 최종 보고서는 실행 안내와 RUNBOOK의 사용자에게 보이는 전달 폴더에 저장하며 Git에서 제외한다.

## 3. UI 확인 순서

모델별 참여 사이트를 먼저 확정한다. `models[].services`에 대상 사이트, `excluded_services`에 나머지 사이트의 제외 사유를 기록한다. 최소 2개 사이트가 있어야 비교 그룹이다. 미제공은 실패/0점이 아니며, 미확인은 미제공과 구분한다. 예: GPT는 3사, Gemini/Claude는 MonoGPT·Timely 2사. 제공 여부가 확인되지 않은 서비스는 자동으로 제외하지 않는다.

전체 항목은 `cases/core.json`의 8개(교육·기획·요약·계산·코드·이미지·파일 분석·파일 생성)이며 항목당 기본 1개다. `cases/smoke.json`은 별도의 초기 연결 점검용이다. 파일 정답과 검토 기록이 준비되기 전에는 이미지/파일 분석을 비활성화한다. 파일 생성은 실제 다운로드 검증 전 성공으로 채점하지 않는다.

1. 사용자가 지정한 브라우저의 로그인 상태를 확인하고 테스트용 새 탭을 연다. 비밀번호·쿠키는 추출하지 않는다.
2. 새 대화에서 정확한 모델을 고른 뒤 추론 수준과 검색 등 노출된 설정을 확인한다.
3. 승인된 요청 수와 지출 조건, 차감 확인 위치를 기록한다. 가격 상한이 없으면 그 한계를 알리고 요청 범위를 별도로 승인받는다. 결제·자동 충전은 하지 않는다.
4. 프롬프트를 원문 그대로 붙여넣고 실제 입력창의 내용과 대조한다. 한글 타이핑 중 글자 누락이 발생하면 전송 전에 교정한다. 붙여넣기만으로 동일성이 보장되는 것은 아니다.
5. [실행 안내](REPRODUCIBLE-RUN.md)의 reserve → timer-start → UI 전송 1회 → 완료 확인 → timer-complete → result 순서를 따른다. 매 요청 status로 시간 저장을 확인한다. 외부 도구 오버헤드가 포함된 완료 관측 상한이며 정밀 서버 응답 시간처럼 표시하지 않는다.
6. 첫 전송 후 새 대화 화면으로 이동할 때 설정이 초기화되는지 확인한다. 결과에 붙은 요청별 모델·추론 표기와 다음 입력용 선택창을 구분한다. 상충하거나 요청별 근거가 없으면 동일 조건 비교를 보류한다. 자동 재전송은 하지 않는다.
7. 결과 원문, 잔액, 사용 내역, 생성 파일을 runs/에만 저장한다. 스크린샷에서는 무관한 채팅 목록을 숨긴다.

## 4. 전송 직전 체크리스트

- [ ] 이번 비교의 서비스·모델·요청 수·지출 조건이 승인돼 있다.
- [ ] 새 테스트는 빈 대화이고, 후속 질문은 지정한 같은 대화이다.
- [ ] 모델 정확한 이름과 접미사가 일치한다. 추론 단계도 일치하거나, 승인된 자동/확인 참고 비교 정책으로 사이트별 차이를 기록했다.
- [ ] 검색·리서치·스킬·커넥터 등 추가 도구 상태를 확인했다. 불명확한 상태를 꺼짐으로 쓰지 않았다.
- [ ] 입력창 원문을 원본과 대조했다. 프롬프트 고도화·자동 재작성은 쓰지 않았다.
- [ ] 첨부 파일은 승인·검토·해시가 동일하며 업로드가 끝났다.
- [ ] 전 잔액과 요청별 소진내역 기준점을 저장했다.
- [ ] 전송은 한 번만 누르고, 완료/오류/차감 확정 전에 재시도하지 않는다.

## 5. 버튼을 못 찾거나 상태가 이상할 때

| 상황 | 다음 행동 | 하지 않을 것 |
|---|---|---|
| 새 탭인데 예전 대화가 보임 | 새 채팅 버튼과 빈 상태 확인 | 홈 URL만 믿고 전송 |
| 옵션이 없음 | 모델 확인 → 옵션 펼치기 → 지원 여부 확인 | `none`이라고 추정 |
| 버튼 이름이 중복됨 | 현재 답변/입력창 범위와 아이콘을 함께 확인 | 첫 번째 요소를 무조건 클릭 |
| 전송 후 추론 표시가 달라짐 | 전후 화면과 답변별 근거를 저장하고 비교 보류 | 자동 재전송 또는 동일 조건으로 채점 |
| 반응 없음 / 타임아웃 | 화면·대화·소진내역 확인; 2~3회 조작 실패 시 사용자에게 위치/상태 질문 | 연속 클릭·중복 질문 |
| 잔액과 소진내역이 안 맞음 | 공유 사용·환급·반영 지연을 확인 | 비용을 임의로 0 또는 확정값 처리 |
| 업로드 제한 / 파싱 오류 | 파일·모델·오류 메시지 기록 | 개인 파일로 대체하거나 미지원과 저품질 혼합 |

## 6. 중단과 재개

요청 수 상한 도달, 인증 실패, 중복 전송 위험은 해당 요청을 보류한다. 추론 조건만 불확실/불일치이면 EXECUTION-RELIABILITY.md의 자동 참고 비교 또는 한 번 확인 경로를 사용하며 모델을 조용히 생략하지 않는다. 비용 귀속 불확실은 미확정으로 표시하고 해당 요청 대조를 마친 뒤 승인 범위의 다음 요청을 진행한다. 시간 누락은 중복 재전송 없이 시계 경로를 고쳐 다음 요청부터 기록한다. 실제 결과는 보존하며 비교 가능한 범위를 분리한다.

화면 캡처와 실행 기록은 `runs/<run-id>/`에 보관한다. Git에는 이 지침과 공통 설정만 포함한다. 다른 사용자는 자신의 브라우저에서 새 화면 근거를 확보해야 하며, 이 사용자의 세션·잔액·화면 파일을 전달받을 필요가 없다.
