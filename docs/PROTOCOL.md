# 실행 및 측정 규약

## 단계

1. 브라우저 도구·계정·사이트 URL·모델·추론·요금·예산을 확인합니다.
2. 공통 모델 버전과 추론 수준을 고정합니다. 웹검색, 메모리, 도구, 출력 제한 등 노출된 설정을 최대한 일치시킵니다. 미공개 항목은 명시합니다.
3. 프롬프트 원문과 첨부 파일의 SHA256으로 동일 입력을 확인합니다. 해시는 입력 동일성의 근거이며 안전성 판정은 아닙니다.
4. 각 테스트는 새 대화에서 시작합니다. 한 테스트의 `turns`는 같은 대화에서 순서대로 실행합니다.
5. 실행 전 잔액을 확인하고 요청을 전송합니다. 응답과 생성 파일을 확보하고 실행 후 잔액을 다시 확인합니다.
6. 기준과 증거를 보존하며 평가하고 결과를 생성합니다.

## 모델 비교의 증거 수준

후보 이름과 실제 모델은 구분합니다. 사이트별 `canonical_model`, `version`, `reasoning`, `feature_settings`가 일치해야 합니다. `reasoning`은 `mode`, `level`, `budget_tokens`를 기록합니다. 실제로 옵션이 없다는 확인 근거 없이 `none`으로 채우지 않습니다.

`evidence_scope`는 `provider_documented` 또는 `ui_declared`입니다. UI 선언만 확인된 경우 보고서에 "표시 조건 일치, 실제 백엔드 버전 미검증"이라고 표시합니다. 다른 서비스의 시스템 프롬프트와 내부 전처리는 같다고 보장할 수 없습니다. 따라서 결과는 서비스 이용 경험의 비교이지 모델 자체의 절대 성능 평가가 아닙니다.

추론 단계가 양쪽에서 같지 않으면 엄격 비교로 위장하지 않습니다. 승인된 실행 설정의 `reasoning_mismatch_policy=auto_exploratory`이면 같은 모델·버전·입력·기타 기능을 유지하고 실제 사이트별 단계와 차이를 기록한 **참고(탐색) 비교**로 자동 진행합니다. `ask` 또는 승인 범위 불명확이면 한 번 확인하며, 조용히 모델을 생략하지 않습니다. 명시적으로 지정한 단계가 우선이고 없으면 가능한 낮은/기본 단계를 선택합니다. 옵션 미노출은 `unknown`이지 추론 꺼짐이 아닙니다. MonoGPT 기본/Timely 보통을 다른 계정에 하드코딩하지 않습니다. 자세한 필드는 EXECUTION-RELIABILITY.md를 따릅니다. 기능이 다른 모델로 실행되었다는 소진내역이 나타나면 해당 파일 결과는 서비스 기능으로만 보고 모델별 성능 점수에서 분리합니다.

## 비용

- 차감량 = 실행 전 잔액 − 실행 후 잔액. 보고서 원화 환산은 해당 실행 사용자가 입력한 서비스별 원/크레딧을 적용합니다. 사용자 입력 기준임을 명시하고 실제 청구액으로 단정하지 않습니다. 입력되지 않은 환산율은 추정하지 않습니다.
- 입력·출력 토큰은 서비스가 제공할 때만 기록합니다. 잔액 차이로 입력/출력 토큰을 추정하지 않습니다.
- 반영 대기 → 정해진 간격 재확인 → 제한 시간 초과 시 미확정으로 남깁니다. 반영 전 요청을 겹쳐 실행하지 않습니다.
- 잔액 0차이는 반영 완료와 표시 정밀도를 확인하기 전에는 무료의 근거가 아닙니다.
- 한도 화면에서 잔액이 0으로 잘려도 사용량 카운터는 계속 증가할 수 있습니다. 전후 사용량 증가를 비용 근거로 기록하고, 잔액 0차이를 0크레딧으로 확정하지 않습니다. 확인되지 않은 전송 시도도 0비용으로 채우지 않습니다.
- 잔액 증가, 충전, 환불, 다른 사용자의 활동이 섞이면 해당 차감 측정은 무효입니다.
- 시도마다 별도 기록하며 실패 요청 비용과 전체 실행 비용도 포함합니다. 재시도는 기본 0회이며 중복 전송 여부와 예산을 확인한 뒤 결정합니다.
- `max_total_requests`와 서비스별 예산을 적용합니다. 후속 질문도 한 요청으로 계산합니다.
- 실제 비용을 미리 확정할 수 없다면 요청당 보수적 비용 상한을 설정하고 지출 확정 전까지 해당 금액을 예약합니다. 엄밀한 상한을 구할 수 없으면 비용 제한의 한계를 알리고 실행 범위를 조정합니다. 계획의 상한 값 자체는 가격 검증을 대신하지 않습니다.

## 시간

전송, 최초 응답 관측, 완료 관측에 대한 시각과 단조 증가 시계값을 기록합니다. UI 준비/첨부/메뉴 이동 시간은 별도로 측정합니다. 관측 방식·간격·오차를 함께 기록합니다. 백그라운드 탭 지연이나 자동화 오버헤드를 모델 지연으로 단정하지 않습니다.

완료 감지 중 다른 사이트 설정·코딩·문서 작업을 하지 않습니다. 마지막 생성 중~최초 완료 관측을 구간으로 보고하며, 하한만 못 봤으면 상한을 버리지 말고 `≤N초`로 표시합니다. 전송/완료 시계가 없을 때만 시간 미관측입니다. 사이트가 표시한 ‘작업 시간’과 외부 관측 시간은 별도 필드입니다. 오래 관측하지 않아 넓어진 구간은 속도 순위에서 제외합니다. 첫 실제 요청 뒤 시간 필드가 저장됐는지 확인하고, 누락되면 중복 전송 없이 원래 시각 근거를 대조한 뒤 남은 요청부터 측정 경로를 바로잡습니다. 기록이 없던 과거 시간을 추정해서 채우지 않습니다.

파일 요청은 첨부 전 잔액·전송 전 잔액·답변 후 잔액을 기록합니다. 업로드/OCR/임베딩에 비용이 생길 수 있습니다. 공용 잔액에서 다른 모델·프롬프트 고도화 같은 별도 내역이 발견되면 전체 잔액 차이를 해당 테스트 비용으로 귀속하지 않습니다. 청구·할인·환불을 구분하고 대화 ID가 없을 때의 귀속 한계를 남깁니다.

## 결과·오류·평가

각 기록에는 실행 ID, 비교 묶음 ID, 서비스, 모델 선언/증거, 추론/기능 설정, 테스트/턴/시도, 입력 해시, 원문, 시간, 전후 잔액, 단위, 환산 근거, 증거 경로, 상태를 담습니다.

상태는 `success`, `unsupported`, `auth_required`, `automation_error`, `service_error`, `timeout`, `measurement_unavailable` 등을 구분합니다. 자동화 실패와 서비스 실패를 혼합하지 않습니다.

정확도·지시 준수·파일 판독은 정답/원본 대조로 평가합니다. 생성했다는 응답만으로 파일 생성 성공으로 채점하지 않고 실제 다운로드·열기·내용을 검증합니다. 주관적 평가는 서비스명을 가리고 공통 기준을 적용하되 평가자와 판단 근거를 남깁니다. UX는 단계 수·오류 복구 등의 관측과 평가자의 해석을 구분합니다. 서비스별 원시 크레딧 수치는 서로 다른 단위이므로 그대로 비용 순위를 매기지 않습니다.

## 반복성과 확장

여러 번 반복할 때 서비스 실행 순서를 순환하거나 무작위화하고 순서를 기록합니다. 작은 표본의 결과를 보편적 순위로 일반화하지 않습니다. 프롬프트·정답·모델·설정 버전이 바뀌면 이전 결과와의 비교 가능성을 검토합니다.

새 사이트는 `sites/CONTRACT.md`의 규격대로 연결하고 소규모 시험 실행을 통과한 후 추가합니다. URL 추가만으로 자동화가 완성됐다고 간주하지 않습니다.
