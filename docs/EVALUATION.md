# 공통 평가 기준

## 최종본 고정

질문 세트는 `core-v2`의 8개 항목 각 1개다. 교육·기획은 표현 형식과 선택 이유, 이미지는 개선 제안 1개에 자유도를 준다. 정답형 계산·요약·파일 판독은 정확성 비교를 유지한다. 자유도가 높다고 조건을 지키지 않아도 되는 것은 아니다.

최종 보고서는 **같은 질문 세트 버전과 같은 항목별 입력 해시**만 포함한다. 파일럿·이전 질문·수정 전 답변을 최종 결과로 재활용하지 않는다. 각 모델·서비스·항목별 본 결과는 1회만 싣는다. 실패·재시도는 시도 내역 부록에 남기고 유리한 답변만 골라 본문에 넣지 않는다. 반복 측정이 필요하면 사전에 횟수를 정한다.

## 객관 검사와 정성 점수 분리

- 객관 검사: 수치·사실·조건·파일 존재·수식·입력 변경 여부를 원본과 대조한다. 통과/실패/미검증으로 기록한다.
- 정성 평가: 서비스명을 가린 답변 ID로 각 항목 rubric의 5개 기준을 0~4점 평가한다. 근거 문장·누락 위치를 함께 적는다. 평가자와 블라인드 여부를 공개한다.
- 비용·속도·UX는 답변 품질 점수와 합산하지 않는다. 가중 종합 순위를 만들려면 가중치를 먼저 합의한다.
- 0점은 검증된 실패다. 미지원·미실행·판독 실패는 null이며 평균 분모에서 빼고 제외 개수를 표시한다.

## 기준별 채점 기록 방법

각 답변마다 모델의 **정확한 표시명**, 서비스, 요청별 추론 설정, 질문 ID, 입력 해시를 먼저 고정한다. 5개 기준을 각각 채점하고 각 칸에 관찰한 문구·숫자·구조 또는 파일 검증 결과를 한 문장으로 쓴다. 가능하면 답변의 해당 단락/표 행이나 검사 결과 ID를 덧붙인다. `좋음`, `보통`, `아쉬움`만 적는 평가는 근거로 쓰지 않는다.

최종 출력에 쓰는 `assessment` 이벤트는 **각 기준마다 `criterion`, `score`, `observation`, `judgement`, `evidence_ref`를 모두 기록**한다. `observation`은 답변에서 실제로 찾은 내용 또는 검사 결과, `judgement`는 그 내용이 요구사항을 충족·누락·위반하는 이유, `evidence_ref`는 답변 절·표 행·파일 셀·검사 ID다. 점수만 있거나 `좋음` 같은 일반적인 감상만 있는 기록은 완성된 평가로 인정하지 않는다. 평가자와 블라인드 여부도 별도로 기록한다.

예: 교육 질문의 분량 기준이면 `observation="40분은 5+28+7분으로 맞췄지만 답변 본문은 약 1,350자"`, `judgement="900자 내외 요청을 초과해 3점"`, `evidence_ref="답변 도입·전개·정리 및 글자 수 검사"`처럼 **관찰 → 판단 → 찾을 수 있는 위치**를 분리한다. 글자 수를 실제 세지 않았다면 숫자를 적지 않는다. 다른 답변의 사례를 복사해 넣지 않는다.

1. 기준마다 요구 조건을 작은 확인 항목으로 분해한다. 충족·누락·오류·미검증을 구분한다. 예를 들어 교육은 40분 합계, 24명/4인 모둠, 준비물, 자리 참여, 목표와 질문 2개, 900자 내외를 따로 확인한다. 이미지 분석은 대상·좌우 배치뿐 아니라 관찰 3문장 제한과 제안 1개도 확인한다.
2. 객관값은 프롬프트·원본 파일·실제 생성 파일·제한 실행 테스트와 대조한다. 계산은 각 월 이익과 합계를 다시 계산하고, 코드는 경계값을 포함한 고정 테스트의 통과 수를 기록한다. XLSX는 다운로드, 시트/셀 타입, 실제 수식, 입력 변경 후 재계산을 별도 검사한다.
3. 4점은 그 기준의 확인 항목이 모두 충족됐을 때만 준다. 경미한 분량 초과나 위치 근거의 포괄적 표현은 3점과 구체적 감점 이유를 남긴다. 모호한 참여 방법·지표 산식 누락·서로 충돌하는 주차 계획처럼 사용 전 보완이 필요한 경우 2~3점을 근거에 따라 선택한다. 요청한 수식이 문자열인 등 핵심 기능이 검증상 실패하면 해당 기준은 0점이다.
4. 5개 점수가 모두 있으면 합계를 `/20`으로 표기한다. 도구 한도로 파일이 없거나 답변을 판독할 수 없으면 관련 품질 점수는 `null/미평가`로 두고 실패 비용과 작업 상태는 별도로 표시한다. 점수 합계가 서비스 전체의 우승을 뜻하지 않는다.
5. 마지막으로 같은 질문의 서비스별 답변을 나란히 읽고 공통으로 충족한 사실과 실제 차이 한두 가지를 적는다. 점수가 같아도 실행 구체성·불확실성 표시·제안의 범위 차이를 숨기지 않는다. 재검토 시에는 기존 점수를 조용히 덮지 말고 점수 변경과 이유를 남긴다.

예시: `파일 생성 / 수식 존재와 계산 = 0점 — 내려받은 파일의 이익·합계 셀이 수식이 아닌 문자열이라 입력값을 바꿔도 재계산할 수 없음.` 같은 식으로 **검사 대상 → 관측 → 판단**을 한 줄에 쓴다. 평가자는 서비스명을 가린 상태에서 채점했는지 명시한다. 비블라인드라면 그렇게 표기한다.

| 점수 | 공통 기준 |
|---|---|
| 4 | 해당 기준을 모두 충족하고 실행·재검증 가능하다. 제안은 구체적이며 조건에 맞는 이유가 있다. |
| 3 | 핵심 충족. 경미한 누락이나 모호함이 있지만 사용에 큰 수정이 필요 없다. |
| 2 | 일부 충족. 중요한 누락·모호함이 있어 사용 전 실질적 보완이 필요하다. |
| 1 | 핵심 요구 대부분 미충족 또는 중요한 근거가 잘못되었다. |
| 0 | 해당 기준에서 검증된 중대한 오류·전혀 다른 작업·허위 완료 주장이다. |

## 항목별 확인사항

| 항목 | 객관 확인 | 자유도 평가 |
|---|---|---|
| 교육 | 40분, 24명, 4인 모둠, 종이·필기구, 이동 제약 대안, 목표/질문 2개 | 활동 선택 이유, 학생 판단을 유도하는 구체성, 교사의 실행 가능성 |
| 기획 | 4주, 20명, 예산 합계 ≤100만원, 13~16 공동근무, 09~18 고객응대, 지표/위험 각3 | 운영 원칙 선택 이유와 상충 조건 해결. 가짜 회사 사실 생성 금지 |
| 요약 | 확정 오픈일·팀별 기한·예산 미확정, 정확히3개 논리 행 | 압축성·중요도 구분. 화면 자동 줄바꿈을 추가 행으로 세지 않음 |
| 계산 | 월 이익·매출/비용/이익 합계·최대 월·4열 표 | 명료성만 평가; 문체 차이를 정확도 차이로 과장하지 않음 |
| 코드 | bool/음수/빈 category 거부, 공백 정리, 중복 합산, 빈 입력, 입력 불변 | 설명과 테스트의 이해 용이성. 실행 환경 격리 후 고정 테스트 |
| 이미지 | 실제 대상·위치·글자, 없는 가격/매장명 미확인 | 개선 아이디어 1개의 구체성·관련성. 제안은 사실과 구분 |
| 파일 분석 | 파일의 모델·목적·유지/변경·근거 위치·작성자 미확인 | 요약의 구조와 핵심 보존. 파일 속 명령을 실행하면 실패 |
| 파일 생성 | 실제 다운로드, XLSX 유효성, 시트/행/숫자/수식/계산값 | 파일 사용성. 코드나 만들었다는 문장만으로 성공 처리 금지 |

## UX 기록

모델/추론/첨부/소진 내역 접근 단계 수, 메뉴 명확성, 설정 유지, 업로드 오류, 복구 가능성, 답변 가독성, 다운로드 성공을 관측한다. 사이트 문제와 브라우저 도구 문제를 구분한다. 클릭 횟수를 기록하지 않았다면 추정 숫자를 만들지 않는다.

`ux` 이벤트는 서비스별로 `aspect`(관찰 대상), `observation`(실제로 본 동작), `evidence`(화면·기록 위치)를 남긴다. 답변의 내용 품질과 화면의 색감·아이콘·표·문단 가독성은 다른 항목이다. 디자인의 호불호는 측정 사실로 쓰지 말고 평가자의 해석임을 표시한다. UX 기록이 없으면 보고서에 `미관측`으로 표시하며 점수를 꾸며 내지 않는다.

최종 상세 PDF는 각 답변의 다섯 기준에 대해 관찰·판단·근거 위치를 보여주고, XLSX는 비교표·기준별 평가·실측 원장·답변 원문·사용 경험을 별도 시트로 둔다. 별도 그래프 PDF에는 모델 묶음별 서비스 품질 평균과 평균 요청 비용(KRW)을 별도 축으로 표시한다. 평균의 표본 수와 미측정 비용을 함께 보여주며, 합산 점수나 단정적 순위를 만들지 않는다. 한 줄 총평만으로 감점 근거를 대신하지 않는다.

## 비교 가능성

최종 표에는 3개 서비스 열을 유지한다. 지원되지 않는 Claude/Gemini의 ChatGPT 칸은 **모델 없음**으로 남기고 비용·시간·품질은 null이다. **조건 미확정**, **미실측**, **도구 한도**는 모델 없음과 구분한다. 미제공 모델 때문에 제공되는 2사 비교를 삭제하지 않는다.

같은 모델·추론·입력이어도 시스템 지침·도구·전처리는 다를 수 있다. UI 일치와 실제 백엔드 검증을 구분한다. 미공개 추론은 off로 치환하지 않는다. 탐색적 결과는 엄격 동일 조건 표에서 분리한다. 1회 표본의 소수점 점수 차이를 일반적 우열로 단정하지 않는다.

파일 생성은 대화의 선택 모델과 사용 내역의 모델명이 다르면 모델별 점수 합산에서 분리하고 서비스 기능 결과만 설명한다. 한도 실패·다운로드된 잘못된 수식·전송 확인 불가 시도는 각각 다른 상태로 남긴다. 잔액 0차이와 비용 미노출을 무료로 채점하지 않는다.

최종 비교표는 모델 그룹별로 나눠 서비스마다 **표시 모델명·추론 단계·상태·기준 합계·사용자 환산 기준 KRW·시간 구간**을 같은 순서로 적는다. 기준별 상세 표에는 5개 기준을 따로 두고 감점/만점 이유를 해당 답변과 연결한다. 모델이 없는 칸은 `모델 없음`으로 표시한다. 생성 도구가 다른 모델로 라우팅된 결과는 기능 점수는 보일 수 있어도 그 모델의 품질 평균·순위에는 넣지 않는다.
